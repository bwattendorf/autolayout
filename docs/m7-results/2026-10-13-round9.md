# Round 9: where do the clearance violations KiCad counts and the verifier doesn't come from?

- Commit: `784e95b` (m7-router; later than abe3432). KiCad 9.0.1. 2026-10-13. Used the existing round-8 files under `out/m7r8_all/`. **The batch was not re-run and no code was changed.**
- Method: for each of the ten boards, `python tools/drc_compare.py <dir>/b_prepared_drc.rpt <dir>/b_routed_drc.rpt --kind clearance --show 10` (and `--kind shorting_items` / `--kind hole_to_hole` where the routed board has any). Classification of the entries was done by a small script I wrote for this round (`round9/r9_classify.py`, plain Python, read-only, imports `tools/drc_compare.py` unmodified). "New" means what `drc_compare.py` calls new: an entry in the routed report with no entry of the same kind and the same item positions in the prepared report.
- As the doc says, `new` counts for silk and unconnected kinds can be inflated by shifted coordinates; I ignore them. For unconnected_items the "new" counts printed in the per-board tables are 0-4 although before/after fall from hundreds to 0-61.
- This log reports facts and counts only; it does not say whose fault anything is.
